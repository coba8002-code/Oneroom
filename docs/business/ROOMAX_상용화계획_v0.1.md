# ROOMAX 상용화 서비스 계획 v0.1 — 회원가입 기반

작성일: 2026-10-16 · 상태: 초안 (검증 전 가정 포함)

> **읽는 법**
> - **[근거]** 출처가 있는 사실. 대부분 언론·리뷰 등 **2차 출처**이며, 원문 대조가 필요한 항목은 *(원문 확인 필요)* 로 표시
> - **[가정]** 아직 검증하지 않은 계획값. 베타 운영으로 확인한 뒤 고칠 숫자
> - **[구현됨]** 현재 코드에 이미 있는 것 (PR #1)

## Ⅰ. 핵심 요약

1. **무엇을 파나**
   - 다가구·원룸 건물 임대인을 위한 "통장 기반 임대 장부" 웹서비스
   - 통장 내역을 올리면 호실별 월세 수납을 맞추고, 공용 운영비와 생활비를 갈라 순수익(NOI)까지 계산
2. **왜 지금인가**
   - 월세 비중이 계속 올라 비아파트는 76%가 월세입니다. 매달 수납 확인 업무가 늘고 있습니다.
   - 다가구 건물은 약 77만 동입니다. 구분거처 기준으로는 384만 호입니다.
3. **어떻게 상용화하나: 회원가입 퍼널**
   - 흐름: 가입 → 첫 장부 → 첫 매칭 → 2개월 사용 → 유료 전환
   - 무료 플랜으로 들어오게 하고, 자동화·알림·세무자료에 돈을 받는 구조입니다. 해외 Stessa·Avail과 같은 방식입니다.
4. **가장 큰 위험**
   - 자리톡: 임대인 70만, 2025년 매출 125억 원. 무료 고지서와 결제를 이미 장악했습니다.
   - 대응: 정면 경쟁 대신 "통장 정산·결산" 깊이로 차별화합니다. 고지 기능은 2차에 따라잡습니다.
5. **다음 90일**
   - 지인 임대인 10~20명 클로즈드 베타
   - 이메일 인증·비밀번호 재설정·탈퇴·결제 구현
   - 처리방침 법률 검토
   - 주간 퍼널 지표 측정

### 2. 해석
1.1 **목표 고객 (1차)**
   - 원룸·다가구 1~3동을 가진 개인 임대인
   - 비아파트이고 월세 중심이며, 호실 5~30개 규모
1.2 **수요 근거**
   - 월세 비중이 커지면서 매달 "누가 냈나" 확인 업무가 늘었습니다.
   - 한 통장에 생활비가 섞여 있어 결산하기 어렵습니다. PRD 원 사용자(본인 건물)가 바로 이 상황입니다.
1.3 **주의**
   - 위 숫자는 "건물·호실 수"입니다. 임대인 수(사람 수)와 같지 않습니다.
   - 시장 규모를 금액으로 환산하지 않았습니다. 근거 없는 TAM 금액은 쓰지 않습니다.

### 3. 여기서 얻는 결론
3.1 **공통 패턴**
   - 소형 임대인은 무료로 들어오게 하고, 자동화·관리 기능에 저가 구독을 받습니다.
   - 큰 돈은 결제·뱅킹에서 나옵니다.
3.2 **지불의사의 한계**
   - Avail은 "90% 이상이 무료 사용"입니다.
   - 따라서 **전환율을 낙관하면 안 됩니다.** 유료 가치는 "시간을 아껴 주는 자동화"와 "세금 신고 자료"에 둡니다.
3.3 **ROOMAX의 자리**
   - 자리톡: 고지와 결제 중심, 임차인 네트워크
   - 렌트플로우: 기업·위탁관리사(PMC) 중심
   - ROOMAX: **개인 임대인의 통장 정산 → 결산 → 세무자료**
     - 근거: 생활비·주인세대 분리와 NOI 계산은 위 서비스 설명에서 확인되지 않은 기능입니다.
     - 이것이 차별점입니다. 경쟁사 기능은 계속 다시 확인해야 합니다.

## Ⅳ. 회원가입 기반 상용화 구조 (핵심)

### 1. 가입 퍼널과 "첫 가치" 시점

| 단계 | 사용자 행동 | 측정 이벤트 (이미 기록됨) | 상태 |
|---|---|---|---|
| ① 가입 | 이메일·사업장 이름·필수 동의 | `auth.signup` | [구현됨] |
| ② 첫 장부 | 호실 CSV 또는 직접 입력 | `onboarding.create` | [구현됨] |
| ③ 첫 통장 | 은행 CSV/XLSX 업로드 | `transactions.import` | [구현됨] |
| ④ **첫 가치(Aha)** | 매칭 결과 확인, "자동 확정 n건" | `matching.run` | [구현됨] |
| ⑤ 습관 | 2개월 연속 통장 업로드 | 월별 `transactions.import` | [구현됨] |
| ⑥ 유료 전환 | 유료 기능 사용 시 결제 | (결제 이벤트) | 미구현 |

- **이미 쓸 수 있는 데이터**
  - 위 이벤트는 모두 `audit_logs`에 사업장별·시각별로 남습니다. 지금 바로 SQL로 퍼널을 볼 수 있습니다.
  - 개인정보는 남기지 않습니다.
- **목표 [가정]** (베타 2개월 뒤 실측해서 고칩니다)
  - 가입→②: 70%
  - ②→④: 50%
  - ④→⑤: 40%

### 2. 요금제 초안 [가정]

| 플랜 | 가격(월) | 범위 | 비교 기준 |
|---|---|---|---|
| **무료** | 0원 | 1개 건물·10호실, 수동 매칭·운영비·대시보드·백업 | Avail·Stessa 무료 플랜 |
| **베이직** | 9,900원 | 30호실, 자동 매칭·거래처 규칙, 계약서 OCR 월 20건 | Landlord Studio $12, Stessa $15 |
| **프로** | 19,900원 | 다건물·멤버 초대(관리자·조회), 월세 알림톡 포함, 세무자료 내보내기 | 렌트플로우 임대인 기본 23,000원 |
| **파트너** | 별도 | 세무사·위탁관리인이 여러 사업장 조회 | 렌트플로우 PMC 플랜 |

- **원칙**
  - 데이터 내보내기(백업)는 **무료에도 항상** 제공합니다. 데이터를 볼모로 잡지 않습니다(신뢰).
  - 호실 수로 나눕니다. 소형 임대인의 규모 차이를 반영하기 위해서입니다.
  - 연간 결제는 2개월 할인을 적용합니다 [가정].
- **검증 방법**
  - 베타 사용자 인터뷰에서 "얼마면 내겠나"를 묻습니다.
  - 가격을 두 가지로 나눠 보여 주는 테스트를 합니다.

### 3. 단위 원가 (변동비) [근거 + 가정]
3.1 **알림톡**
   - 시장가: 건당 약 5~15원 (딜러사 블로그, 2차 출처)
   - 실패하면 SMS로 대체되며, SMS는 18원입니다 (솔라피 요금 페이지).
3.2 **계산 예시**
   - 9호실 건물에서 월 1회 고지 + 미납 1회 안내 = 약 18건
   - 18건 × 15원 = **월 약 270원**
   - 따라서 프로 요금에 포함해도 마진에 미치는 영향이 작습니다.
3.3 **CLOVA OCR**
   - 종량제이고 기본 유지비는 없습니다 (NCP 가이드).
   - **호출당 단가는 공식 확인 못함.** 베타 기간에 실제 청구액을 측정해서 플랜 한도를 정합니다.
3.4 **서버**
   - 사업장 하나당 데이터가 작습니다. 백업 파일 하나가 계약서 1장 포함해서 약 40KB였습니다(실측).
   - 초기에는 고정비(호스팅) 위주로 계산합니다.

### 4. 결제와 돈의 흐름
4.1 **구독 결제**: 정기결제 PG(카드 자동결제)를 씁니다.
4.2 **임대료는 우리가 받지 않습니다**
   - 임대료 대금을 받아서 정산하면 전자지급결제대행(PG) 등록 대상이 될 수 있습니다.
   - PG 규제를 강화하는 개정안이 2025년 11월 국회를 통과했습니다 (법무법인 뉴스레터, 2차 출처).
   - 그래서 **임대료는 임차인 → 임대인 계좌로 그대로** 갑니다. ROOMAX는 통장 내역으로 확인만 합니다.
   - 이 구조는 지금 제품 설계와 같습니다.
4.3 **결제 수익 모델**
   - 자리톡의 카드결제처럼 결제로 수익을 내는 모델은, 등록 PG와 제휴하는 방식으로 3차 이후에 검토합니다.

## Ⅵ. 출시까지 남은 제품 작업

### 1. 이미 된 것 [구현됨]
- **장부 기능**: 가입·로그인·2단계 인증·역할·사업장 격리, 온보딩, 청구, 은행 가져오기, 입금 매칭, 운영비·NOI, 대시보드, 계약서 OCR(검수 후 반영), 암호화 백업·복구
- **품질**: 테스트 109건, PostgreSQL 마이그레이션 검증, 디자인 시안 적용
- **(추가 구현)** 이메일 확인·비밀번호 재설정(SMTP, 업체 미정), 회원 탈퇴·사업장 해지·파기,
  운영 배포 구성(`deploy/` — HTTPS 자동 인증서, 같은 도메인, 운영 설정 검사, 정기 백업). 테스트 138건

### 2. 베타 전 필수
1. **이메일 인증·비밀번호 재설정** — 구현됨. 남은 것: 발송 업체 선정, 처리방침 위탁 목록 추가.
2. **회원 탈퇴와 데이터 파기** — 구현됨 (탈퇴 전 백업 안내 포함).
3. **배포** — 구성 완료(`deploy/`). 남은 것: 서버·도메인 확보, 실제 발급 확인, 서버 밖 백업 복사, **오류 모니터링**
4. **실제 은행 양식 매핑**: 주요 은행 3~5곳의 CSV/XLSX 샘플이 필요합니다.
5. **CLOVA OCR 실연동 검증**: 실제 키로 종이 계약서 10장을 시험합니다.
6. **로그인 시도 제한 저장소**: 서버를 2대 이상 두면 Redis 등으로 옮깁니다.

### 3. 유료 전환 전
1. 요금제 한도(호실 수·OCR 건수) 적용과 결제(PG 정기결제)
2. 멤버 초대 (관리자·조회 권한은 이미 구현됨)
3. 사업자 정보 표시, 통신판매업 신고

### 4. 2차 (경쟁 대응)
- 월세 알림톡 고지와 미납 안내. 자리톡이 이미 하는 기능이므로 따라잡아야 합니다.
- 세무자료 내보내기 (주택임대소득 신고용)
- 전월세 시뮬레이션
