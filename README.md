# ROOMAX

다가구주택(임대 원룸 9호실 + 주인세대) 관리 웹앱. 요구사항: [docs/PRD.md](./docs/PRD.md)

## 구성

```
backend/    FastAPI + SQLAlchemy + Alembic (PostgreSQL)
frontend/   Next.js + TypeScript + Tailwind
deploy/     운영 배포 (docker compose + Caddy HTTPS) — deploy/README.md
            · GitHub → Vercel + Supabase (서버 관리 없음) — deploy/vercel-supabase-guide.md
samples/    온보딩 CSV · 은행 거래 CSV 샘플 (가상 데이터)
docs/       PRD
```

## 실행

```bash
# 1) DB
docker compose up -d db

# 2) 백엔드
cd backend
python -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env            # ROOMAX_FIELD_KEY 를 새로 생성해 넣으세요
alembic upgrade head
uvicorn app.main:app --reload   # http://localhost:8000/docs

# 3) 프런트
cd ../frontend
npm install
npm run dev                     # http://localhost:3000/onboarding
```

### 입금 매칭 규칙

| 상황 | 처리 |
|---|---|
| 입금자명(이름·별칭)이 계약 1건에만 일치 + 금액 = 가장 오래된 미납 청구 잔액 | **자동 확정** (신뢰도 95%) |
| 이름 일치, 금액이 적음 / 많음 / 미납 없음 | 검토 대기 — 부분납부 / 선납 제안 |
| 이름 일치, 금액 = 미수령 보증금 | 검토 대기 — 보증금 수령 제안 (부채, 매출 아님) |
| 입금자 미등록, 같은 금액 청구가 1건 | 검토 대기 — 금액만 일치 (50%) |
| 입금자 미등록, 같은 금액 청구가 여러 건 | 검토 대기 — 호실을 추측하지 않음 |

- 배분은 가장 오래된 미납 청구부터. 남는 돈은 선납 잔액 → 다음 달 청구 생성 시 자동 차감
- 승인할 때 "입금자명 기억"을 고르면 다음 달부터 그 이름으로 자동 확정
- 자동 확정도 취소 가능 → 청구는 미납으로, 거래는 검토 대기로 돌아감 (모든 결정은 `audit_logs`)

| 출금 자동 분류 (기억한 거래처 규칙만 자동 확정, 나머지 제안) | `POST /api/v1/expenses/classify` · `/expenses` 화면 |
| 출금 검토 대기 · 나눠서 확정(혼합 거래) · 규칙 기억 · 확정 취소 | `GET /api/v1/expenses/queue` · `POST /api/v1/transactions/{id}/expense-decision` · `…/expense-cancel` |
| 현금 지출 기록 · 월별 지출 내역 | `POST /api/v1/expenses` · `GET /api/v1/expenses?period=` |
| 기억한 거래처 규칙 조회·삭제 | `GET/DELETE /api/v1/expense-rules` |
| 월 결산 — 순운영수익(NOI) | `GET /api/v1/reports/monthly?period=` |

### 운영비 분류

| 구분 | 분류 | 순운영수익(NOI) |
|---|---|---|
| 운영비 | 공용전기 · 수도 · 청소 · 수리(호실 지정 가능) · 공용 기타 | **차감** |
| 운영비 아님 | 주인세대 · 개인 생활비 | **제외** (따로 표시) |
| 부채 | 보증금 수령 · 보증금 반환 | **제외** (따로 표시) |

- NOI = 그 달 확정된 월세 입금 − 그 달 운영비. 그 달 미확정 거래가 있으면 "확정 전 수치"로 표시
- 자동 확정은 관리자가 확정하며 **기억**한 거래처와 정확히 같을 때만. 키워드(한국전력·수도·청소·마트 등)는 제안까지만
- 혼합 거래(예: 마트 = 생활비 + 주인세대)는 금액을 나눠 확정, 합계가 거래금액과 다르면 거부. 기억하면 같은 비율로 자동 배분
- 받는 분이 임차인이고 금액이 받은 보증금과 같으면 보증금 반환 제안 → 확정 시 `deposits.returned_at` 기록

| 홈 대시보드 (호실 현황·이번 달 수지·납부 예정·계약 만료·세금 일정·확인 필요) | `GET /api/v1/dashboard?as_of=` · `/` 화면 |
| 은행 거래 가져오기 (수납 화면에서 언제든) | `GET /api/v1/bank-accounts` · `/payments` 화면 |

### 홈 대시보드

- **확인 필요**: 은행 내역 없음/7일 이상 끊김, 이번 달 청구 미생성(바로 생성 버튼), 입금·출금 검토 대기,
  납부일 지난 미수, 보증금 수령 기록 없음, 60일 안 계약 만료(반환할 보증금), 공실
- **미수 표시**: 은행 내역이 없거나 오래됐거나 입금 검토가 남아 있으면 납부일이 지나도 "미수"가 아니라
  **"확인 필요"**로 표시 (PRD §4 — 납부일 경과만으로 미납 단정 금지)
- **모르는 값은 '—'**: 그 달 청구를 만들기 전이면 청구액, 은행 내역 기간이 그 달과 겹치지 않으면 입금·운영비·순운영수익을
  0원이 아니라 `null`(화면 '—')로 두고 이유를 함께 표시 (월 결산 `GET /api/v1/reports/monthly` 도 같은 규칙, `charges_ready`·`bank_covered`)
- **세금 일정**: 일반 법정 일정만(사업장현황신고·종소세·재산세·중간예납·종부세). 해당 여부는 판정하지 않음

| 계약서 등록 (촬영·파일) → 클라우드 OCR → 관리자 검수 → 원장 반영 | `/contracts` 화면 · `POST /api/v1/leases/{id}/documents` · `POST /api/v1/documents/{id}/verify` |

### 계약서 OCR (NAVER CLOVA OCR)

1. NAVER Cloud 콘솔 → CLOVA OCR → **General** 도메인 생성 → API Gateway 연동 → Invoke URL · Secret Key 발급
2. `backend/.env` 에 `ROOMAX_CLOVA_OCR_URL` · `ROOMAX_CLOVA_OCR_SECRET` 입력 후 서버 재시작
3. 설정 전에도 계약서 업로드·검수는 됩니다 (값을 직접 입력)

- 계약서 원본은 서버에 **암호화 저장** (`ROOMAX_UPLOAD_DIR`, 키는 `ROOMAX_FIELD_KEY`) — 백업 대상에 포함하세요
- OCR 은 보증금 · 월세 · 납부일 · 계약 시작/종료만 **후보**로 뽑습니다 (근거 문장 표시, 이름·연락처는 뽑지 않음, 못 찾으면 빈칸)
- **검수 완료를 눌러야만** 계약(원장)에 반영되고 전후 값이 `audit_logs` 에 남습니다
- 월세·납부일 변경은 다음에 만드는 청구부터 적용
- **보증금 증액**: 검수 화면에서 보증금을 올리면 이미 받은 금액은 그대로 두고 **차액만 '받을 보증금'**으로 등록
  (보증금은 받은 묶음별로 기록 — 최초분·증액분). 증액분 입금은 매칭이 '보증금 수령'으로 제안하고, 확정하면 부채로 기록
  (월세 입금·NOI 에 안 들어감). 이미 받은 금액보다 낮추는 것은 거부 — 일부 반환은 반환 출금으로 처리.
  만기 반환은 받은 묶음 합계(최초분+증액분)와 같은 출금을 '보증금 반환'으로 제안

## 회원가입 · 로그인 · 권한

- **회원가입 = 사업장 생성**: 가입한 사람이 그 사업장의 대표(owner). 이용약관·개인정보 동의(필수), 광고성 정보 수신(선택,
  기본 꺼짐, 설정에서 철회) 일시를 기록. 약관·처리방침은 `/terms` `/privacy` (**초안 — 법률 검토 필요**)
- **로그인 세션**: HttpOnly 쿠키, DB 에는 토큰 해시만. 로그아웃·비밀번호 변경 시 서버에서 폐기. 5회 실패 시 15분 잠금
- **모든 업무 API 는 로그인 필요**, 남의 사업장 데이터는 404 (테스트가 모든 경로를 훑어 검사)
- **역할**: owner(전체) · manager(입력·수정) · viewer(조회만). 백업·복구는 owner 만
- **멤버 초대** (설정 → 멤버, 대표만): 이메일 + 권한(관리자·조회)으로 초대 → 메일 링크(7일, 1회용, DB 에는 해시만)에서 이름·비밀번호를
  정하면 그 사업장 계정이 만들어지고 로그인. 메일 링크로 왔으므로 이메일 확인 완료로 처리. 같은 주소로 다시 초대하면 이전 링크 무효,
  사업장당 하루 20통. 권한 변경은 다음 요청부터 바로 적용, 내보내면 그 계정 삭제·즉시 로그아웃(입력한 기록은 남음).
  한 계정은 한 사업장에만 속하므로 다른 사업장에 이미 가입한 이메일은 수락 단계에서 안내 (초대할 때는 가입 여부를 알려주지 않음).
  초대 이메일은 수락·취소하면 즉시, 만료되면 30일 뒤 삭제. `GET/POST /api/v1/members…` · `POST /api/v1/auth/invitation/{preview,accept}`
- **2단계 인증(MFA)**: 인증 앱 TOTP, 설정에서 켜기
- **이메일 확인 · 비밀번호 재설정**: 가입 직후 확인 메일(24시간), `/forgot-password` 에서 재설정 메일(1시간). 링크는 한 번만,
  DB 에는 토큰 해시만. 재설정 요청은 가입 여부와 관계없이 같은 응답, 주소당 시간당 3통. 재설정하면 모든 기기 로그아웃
  (2단계 인증은 유지). 미확인 계정도 이용 가능, 화면 위에 안내 배너
- **메일 발송 설정**: 개발은 `ROOMAX_MAIL_MODE=file` (보내지 않고 `mail_outbox/` 에 .eml 저장), 운영은 `smtp` +
  `ROOMAX_SMTP_HOST/PORT/USER/PASSWORD`, `ROOMAX_MAIL_FROM`, 링크 주소 `ROOMAX_APP_URL`. 업체를 정하면 처리방침 '처리 위탁'에 기재
- 운영(HTTPS)에서는 `ROOMAX_COOKIE_SECURE=true`, 화면과 API 를 같은 도메인(리버스 프록시)으로 두는 것을 권장

## 회원 탈퇴 · 사업장 해지 (`/settings` 맨 아래)

| 누가 | 지워지는 것 | 남는 것 |
|---|---|---|
| 대표(owner) = **사업장 해지** | 그 사업장의 모든 업무 데이터(임차인·계약·거래·운영비·변경 기록) + 계약서 파일 + 복구 직전 안전 백업 + 그 사업장의 **모든 계정**(세션·메일 토큰) | 개인정보 없는 파기 기록 1줄 (일시·테이블별 건수) |
| 관리자 · 조회 | 그 계정과 세션·메일 토큰, 계정 자체의 기록 | 사업장 데이터·변경 기록 (작성자 연결만 끊음) |

- 지우기 전에 무엇이 몇 건 지워지는지 미리 보여주고(`GET /api/v1/auth/account/deletion-preview`), 백업 내려받기를 권함
- 실행(`POST /api/v1/auth/account/delete`)은 **비밀번호 재확인 + 2단계 코드(켜져 있으면) + 대표는 사업장 이름 입력**
- DB 는 한 트랜잭션(실패하면 아무것도 안 지워짐), 파일은 커밋 뒤에 삭제. 다른 사업장은 건드리지 않음 (테스트·PostgreSQL 외래키로 확인)
- 서버 정기 백업(`backup_cli --keep`)에 남은 사본은 보관 개수만큼 지나면 순환 삭제 — 처리방침에 기재

## 백업 · 복구 (`/settings`)

- **백업 파일 하나** (`.roomaxbak`): 사업장의 모든 데이터 + 계약서 원본. 사용자가 정한 비밀번호로 파일 전체를
  암호화 (scrypt → AES-256-GCM). 서버 키와 무관해서 **다른 서버·새 키로도 복구**됩니다. 비밀번호를 잃으면 복구 불가
- **복구 전 확인**: 사업장 이름·백업 시각·건수·버전 호환 여부를 먼저 보여줌
- **복구 대상은 로그인한 사업장**: 다른 서버·다른 사업장에서 만든 백업도 이 사업장으로 옮겨 넣음. 계정 정보(비밀번호·세션)는
  백업에 넣지 않음
- **덮어쓰기**: 이 사업장에 이미 데이터가 있으면 사업장 이름을 입력해야 진행. 직전 상태를 `ROOMAX_BACKUP_DIR` 에 같은
  비밀번호로 자동 백업. DB 는 한 트랜잭션이라 실패하면 아무것도 바뀌지 않음. 감사 기록은 되감지 않고 보존
- **서버 정기 백업**: `ROOMAX_BACKUP_PASSPHRASE='…' python -m app.backup_cli --out /srv/roomax-backups --keep 30`
  (cron 예시는 설정 화면에). 백업 폴더는 다른 디스크·외부 저장소로 한 번 더 복사 권장
- 대시보드는 백업한 적이 없거나 30일이 지나면 알려줌

## 알림·메시지 (`/notifications`) — 알림톡은 향후 연결

- **월세 고지**(그 달 청구마다, 이미 낸 호실 제외)와 **미납 안내** 초안을 만들고, 관리자가 내용을 확인·수정해 **승인**해야 보낼 수 있음
- **미납 안내 초안은 세 조건이 모두 있을 때만**: 관리자가 정한 유예기간 경과 + 은행 내역이 유예기간 끝까지 반영 + 입금 검토 대기 없음
  (PRD §4 자동 독촉 금지). 조건이 안 되면 만들지 않고 호실별 이유를 보여줌
- **유예기간·문구는 관리자가 화면에서 정함** — 기본값 없음. 문구에 `{임차인}` `{호실}` `{청구월}` `{금액}` `{납부일}` `{미납액}` `{경과일}` 칸
- **계약 만료 안내**(갱신 거절·조건 변경 통지): 그날이 그 계약의 **갱신 통지 기간(만료 6개월 전~2개월 전, 주택임대차보호법 §6)** 일 때만
  초안을 만듦. 갱신할지·조건을 바꿀지는 관리자가 문구로 정함(기본 문구 없음). 칸 `{임차인}` `{호실}` `{월세}` `{보증금}` `{계약시작일}` `{만료일}` `{통지마감일}`.
  안내는 만료일별로 기록돼, 갱신으로 만료일이 바뀌면 새로 만들어야 함
- **홈 '계약 만료 · 갱신 통지'**: 통지 기간이 열리기 30일 전부터 보여 줌. 기간 안인데 보낸 안내가 없으면 경고, 기간이 지났는데 기록이 없으면
  '같은 조건으로 2년 갱신된 것으로 봄(§6①·②) — 임차인과 확인' 안내. 날짜는 달력으로 거꾸로 센 참고값(그 달에 같은 날이 없으면 말일)
- **알림톡 연결 전**: 승인한 문구를 복사해 문자·카톡으로 직접 보내고 '보냄으로 표시' (기록: 승인 시각·보낸 시각·방법)
- **연결할 때**: `backend/app/services/messaging.py` 에 업체 구현을 등록하고 `ROOMAX_ALIMTALK_PROVIDER`·`_API_KEY`·`_SENDER_KEY` 설정 →
  승인과 동시에 발송, 실패하면 이유를 남기고 직접 보냄으로 처리 가능

## 호실·계약 (`/units`)

- 호실마다 진행 중·지난 계약 이력. **계약 종료**: 종료일(실제 퇴거일) 뒤에 납부일이 오는 청구 중 아무것도 안 낸 것은 '받지 않음'(월 청구는
  일할 없이 전액이므로), 일부 입금된 청구는 그대로 두고 알림. 호실은 공실로, 다음 달 청구에서 빠짐. 남은 미납·미반환 보증금·정산서 미확정을 알려 줌.
  보증금은 돌려줄 때까지 부채 — 홈에서 계속 경고. **종료 되돌리기**(그 호실에 새 계약이 없을 때, 면제한 청구도 되살림)
- **새 계약**: 공실 호실에 임차인·보증금·월세·납부일·계약일·시작/만료일. 앞 계약 종료일 뒤로만. 보증금은 은행 입금을 '보증금 수령'으로 확정하면 기록
- **법정 체크**: ① 선순위 임대차 정보 제시(주임법 §3조의7 1호) ② 납세증명서 제시·열람 동의(같은 조 2호) ③ 임대차 신고(부동산거래신고법 §6조의2 —
  보증금 6천만 원 초과 또는 월세 30만 원 초과, 계약일부터 30일, 군 지역 제외 → '해당 없음' 표시 가능, 기한 7일 전부터 홈 경고)
  ④ 입주 점검·임차인 확인(자동) ⑤ 보증금 수령(자동). 처리 기록은 날짜·메모와 감사 기록
- **계산기**: 증액 상한(§7 — 5%, 계약·직전 증액 1년 뒤부터, 조례로 더 낮을 수 있음, 새 계약·합의 재계약 제외),
  월차임 전환율(§7조의2 — min(10%, 기준금리+2%), 기준금리는 직접 입력). 원 아래 버림, 참고값

## 입금 알림 실시간 확인 (설정 → 입금 알림 자동 연결)

사업자등록·공동인증서 없이 납부일 당일 입금을 바로 확인하는 방법. 은행 오픈뱅킹 API 는 개인이 쓰기 어렵고
스크래핑은 은행 약관·보안 문제가 있어, **휴대폰이 받은 은행 알림을 그대로 넘겨받는** 방식을 씁니다.

- 계좌별 **비밀 연결 주소** 발급(토큰은 해시만 저장, 원문은 한 번만 표시). 새로 만들면 예전 주소는 바로 끊김
- 안드로이드: MacroDroid 등 자동화 앱이 은행 앱 알림·문자를 POST. 아이폰: 단축어 '메시지' 자동화(은행 문자 알림 필요)
- 본문은 JSON(`text`·`message` 등) · 폼 · 그냥 글자 모두 받음. 응답에 장부 내용을 돌려주지 않음
- 문장에서 입금/출금·금액·입금자·잔액·시각을 **보수적으로** 읽음 — 애매하면 거래를 만들지 않고 '읽지 못함'으로 기록,
  입금자 후보가 여럿이면 비움(→ 금액만으로는 자동 확정 안 됨). 출금 알림은 무시(지출은 통장 내역으로)
- 들어온 입금은 **기존 매칭 규칙 그대로**: 이름·별칭이 계약 1건 + 금액이 가장 오래된 미납 잔액일 때만 자동 확정
- 같은 거래의 문자+앱 푸시·재전송은 중복으로 거름(잔액이 같거나, 잔액을 모르면 같은 이름·몇 분 안)
- **알림은 '들어왔다'의 증거일 뿐** — 은행 내역 기간(미납 판단·결산·미납 안내 조건)은 통장 내역 파일만 셈
- 통장 내역 파일을 올리면 같은 계좌·방향·금액이 30분 안(날짜만 있는 파일은 같은 날)인 알림 거래와 **합침**(확정 유지).
  파일 기간 안인데 짝이 없는 알림 거래는 경고
- 홈 **'오늘 납부일'** 카드: 입금 확인 시각·출처(알림/통장 내역), 화면을 열어 두면 1분마다 새로 고침
- 알림 문장 시험(저장 안 함)·최근 받은 알림 목록. 은행별 형식은 실물 샘플을 받아 보강
- 주소가 새어도 대량 투입을 막도록 계좌당 10분에 30건까지 (`ROOMAX_ALERT_RATE_LIMIT`)
- 은행 앱에서 알림 켜는 법·폰 설정·시험 순서: [docs/bank-alerts-guide.md](./docs/bank-alerts-guide.md) (설정 화면에도 같은 안내)

## 세무 준비 (`/tax`)

- 귀속연도별 **입력자료 모음** — 세액 계산·판정·'신고 확정' 없음(PRD §4). 결과마다 귀속연도·작성 시각·입력자료 상태
  (은행 내역 있는/없는 달, 미확정 거래, 증빙 없는 운영비)
- 월별 청구·입금·운영비. **은행 내역 없는 달은 비우고** 합계는 '자료 있는 달만'으로 표시. 월세는 청구 기준·입금 기준 둘 다(수입 시기는 정하지 않음)
- 연말 기준 보증금 잔액(부채, 간주임대료 판단 입력자료 — 판정은 안 함)
- **지출 증빙**: 영수증·세금계산서 사진/PDF(4MB), 암호화 보관·백업 포함. 증빙이 붙은 지출은 증빙을 먼저 지워야 삭제·확정 취소 가능
- **엑셀**: 요약·월별·경비 내역·보증금 시트

## 전월세 시뮬레이션 (`/simulate`)

- 지금 계약(사실값)에서 시작해 호실별 보증금·월세를 바꿔 보기, 전환율로 '100만·500만 전환' 버튼
- 연 월세 수입·보증금 부채·운용수익·연 순수익·자기자본 수익률(건물 가치 입력 시). 운용 수익률·운영비·현금·건물 가치는 **직접 넣은 값만** —
  비우면 결과도 '—'. 지난 12개월 실제 운영비는 참고로만 표시
- **반환 자금**: 12개월 안 만료 계약의 보증금을 달별·누적으로, 보유 현금과 비교해 부족한 달 표시
- 간주임대료·종합소득세는 계산하지 않음(판정 기준은 세무사 확인)

## 입주·퇴실 (`/move-out`)

- **입주·퇴실 점검**: 계약마다 입주 1번·퇴실 1번. 기본 항목(현관·열쇠·벽지·바닥·욕실·전기/가스/수도 계량기 등) +
  그 호실 **자산대장 품목**으로 점검표를 만들고, 항목마다 상태(양호·생활 마모·오염·파손·없음)·계량기 숫자·메모·사진(항목당 10장).
  모르면 비워 둠. 퇴실 점검은 입주 점검과 같은 항목·순서로 만들어짐
- **사진**: 휴대폰 카메라로 바로. 서버 한도 안으로 줄이고(HEIC·WebP 는 JPEG 로), 계약서처럼 **암호화해 보관**, 올린 시각이 증빙 시각.
  백업 파일·사업장 해지에 함께 포함
- **임차인 확인 · 잠그기**: 함께 확인한 날·방법을 남기면 점검이 잠겨 고칠 수 없음(증빙 보존). '확인 풀기'는 이유와 함께 기록
- **입주↔퇴실 비교**: 같은 항목을 나란히, 상태가 나빠진 항목 표시. 생활 마모는 보통 임차인 부담이 아니라는 안내
- **퇴실 정산서**: 장부에서 온 사실값만 — 돌려줄 보증금(받았고 아직 안 돌려준 묶음) + 선납 잔액 − 기준일까지 납부일이 지난 미납 청구.
  파손·청소·공과금 공제는 관리자가 적고 근거 점검 항목을 연결. **다툼 있는 공제는 '먼저 돌려줄 금액'에서 빼 따로 보관**.
  보증금 수령 기록이 없으면 계산하지 않음. 확정하면 숫자를 고정(스냅숏)하고 공제를 잠금, '확정 풀기'는 이유 기록.
  실제 반환은 은행 출금을 '보증금 반환'으로 확정할 때 기록. 인쇄·PDF 저장 지원
- 경고: 은행 내역 없음·입금 검토 대기(미납이 실제와 다를 수 있음), 퇴실 점검 없음, '생활 마모' 항목에 파손 공제

## 자산·수리 (`/assets`)

- **자산대장**: 호실 옵션·집기와 건물 공용 설비(CCTV·소화기 등). 종류·모델·제조연월(명판)·설치일·구입가·무상 보증·교체 예정월·메모.
  같은 품목을 **여러 호실에 한 번에** 등록. 모르는 칸은 비워 두면 `—` (추정해서 채우지 않음)
- **옵션 vs 임차인 소유** 구분 — 퇴실 때 두고 가는지, 수리 책임이 누구인지가 갈림
- **경과 기간**은 적힌 제조연월(없으면 설치일)로 센 사실값. 수명·교체 시기를 시스템이 추정하지 않음 — 교체 예정월은 관리자가 정함
- **빼기**(교체·폐기·철거)는 기록을 남기고 목록에서만 숨김. 수리 기록이 있는 품목은 지울 수 없음
- **수리 이력**: 위치(공용·호실)·품목·접수일·업체·비용·부담(임대인·임차인·미정)·완료일. 진행 중 수리는 홈 알림에 표시.
  수리비는 기록용 — 월 결산에는 은행 출금을 '수리비'로 분류한 금액만 들어감(이중 계산 방지)
- **교체 계획**: 앞으로 12개월, 옵션 품목을 교체 예정월·종류별로 묶음(같은 달 같은 품목 여럿이면 '함께 구매 검토') — 공동구매 수요 집계의 기초.
  60일 안에 무상 보증이 끝나는 품목
- **엑셀(CSV) 내려받기** (UTF-8 BOM, 엑셀에서 바로 열림)

## 정기 점검·소모품 (`/assets` → 정기 점검)

- 소화기·감지기 점검, 정화조·저수조 청소, 보일러·가스·전기 점검, 도어락 건전지, 화재보험 갱신 같은 **반복되는 일**
- 건물 공용 또는 호실별(여러 호실을 고르면 호실마다 따로), 자산대장 품목에 걸 수도 있음(걸린 품목은 지우기 대신 '빼기')
- **주기·다음 예정일은 직접 정한 값만** — 예시는 이름만 제안하고 법정 주기도 정하지 않음(관할 기관·업체 계약으로 확인).
  예정일을 모르면 비워 두고 '예정일 없음'
- '했음 기록' → 다음 예정일 = 한 날 + 주기(달력, 없는 날은 말일). 주기 없으면 '끝남'.
  가장 최근 기록을 지우면 예정일을 그 전 값으로 되돌림. 기록 있는 일은 지우기 대신 '멈춤'
- 예정일이 지나면 홈 '확인 필요'(경고), 14일 안이면 안내. 비용은 기록용(비용 모르는 기록이 섞이면 합계 비움)

## 공실 관리 (`/vacancy`)

- 공실 호실마다 공실 시작일(직전 계약 종료일)·공실 일수·**놓친 월세**(공실 기간에 돌아온 직전 계약 납부일 수 × 직전 월세 —
  시세 추정 아님). 직전 계약 기록이 없으면 비움
- 모집 조건(보증금·월세·입주 가능일·설명)은 직접 정함 → **광고 문구** 자동 작성(호실·면적·자산대장 옵션·조건에 적힌 값만), 복사해 직방·다방에
- 중개사 등록·문의·방 보기 기록 (중개사 연락처는 암호화 저장)

## AI 비서 (`/assistant`)

- 장부에 대해 묻고 답하기. Claude API(기본 `claude-opus-5-5`, `ROOMAX_AI_MODEL` 로 변경)
- **숫자는 모델이 만들지 않음**: 모델은 읽기 전용 조회 도구 8개(홈 요약·미수·월 결산·계약·만료/갱신·공실·정기 점검/수리·세무 준비)만
  불러 DB 값을 옮김. 답마다 근거(쓴 도구)와 조회 시각 표시, 도구를 안 썼으면 '장부를 조회하지 않은 답'으로 표시
- 장부를 바꾸지 않음(확정·발송·삭제 없음), 세금·법적 판단·독촉 결정 안 함
- **개인정보**: 도구 결과에 임차인 이름·연락처·입금자명·자유 입력 메모를 넣지 않음(테스트로 검사). 질문 원문은 서버에 저장하지 않음.
  처리방침 1.1 에 국외 이전(Anthropic, 미국) 고지
- 비용 보호: 사업장당 하루 질문 수 상한(`ROOMAX_AI_DAILY_LIMIT`, 기본 50), 응답 깊이 낮음(effort low), 안전 분류기 거절 시 서버 측 대체 모델(fallbacks)
- 키가 없으면 화면에 '연결 안 됨' 안내만 (다른 기능 영향 없음)

## 월간 운영 보고서 (`/reports`)

- 한 달을 한 장으로: 월세 청구·확정 입금·미수(기준일 납부일 지남)·운영비 항목·순운영수익·제외 항목(생활비·주인세대)·
  보증금 잔액(부채)·호실별 청구/입금·공실·정기 점검/수리·만료와 갱신 통지
- 기준일 = 그 달 말일(진행 중인 달은 오늘). 오지 않은 달은 만들지 않음
- 은행 내역이 없거나 미확정·검토 대기가 있으면 맨 위에 주의 문구, 모르는 값은 '—' (결산 규칙 그대로)
- 그 달 계약이 있던 호실 수는 계약 기간으로 셈 (현재 상태로 과거를 짐작하지 않음)
- **인쇄·PDF**(A4 한 장, 메뉴·안내 배너 숨김)와 **엑셀**(요약·청구·미수·공실·점검·수리 시트). 임차인 이름·연락처는 넣지 않음

## 임차인 화면 (`/units` → 임차인 링크)

- 진행 중인 계약마다 **초대 링크**를 만들어 문자·카카오톡으로 보냄 — 임차인은 로그인·앱 설치 없이 열고, 문자 인증 업체도 필요 없음
- 유효 기간은 30·90·180·365일 중 관리자가 고름. 새로 만들면 이전 링크는 바로 닫힘, '링크 끄기'로 회수, **계약이 끝나면 자동으로 닫힘**
- 링크(비밀 토큰)는 서버에 해시로만 저장 — 주소는 만들 때 한 번만 보여 줌. 화면은 검색 제외·다른 사이트로 주소를 넘기지 않음
- 임차인이 보는 것: 자기 호실·계약 기간·월세·납부일·보증금(계약 금액, 받은 기록), 최근 12개월 청구와 **확인된 입금**, 다음 납부일
  - 확인되지 않은 청구는 '미납'이 아니라 **'입금 확인 전'**, 통장 내역 반영 시각을 함께 표시 (자동 독촉 금지)
  - 다른 호실·이름·연락처·관리 메모·수리 비용·부담 주체는 보이지 않음
- 임차인이 할 수 있는 일은 **수리 요청**뿐 (하루 5건) → 자산·수리에 '임차인 요청'으로 들어가고 홈에 알림. 처리 상태(처리 중·완료)는 임차인 화면에 보임
- 관리자 화면에 마지막 열람 시각 표시

## 건물 여러 동

- '건물·호실 등록'을 다시 하면 건물이 추가됩니다. 월세 받는 통장은 기존 통장을 함께 쓰거나 새로 등록
- 건물이 2개 이상이면 홈·임대료·계약·자산·공실·메시지·AI 비서 등 **모든 화면에서 호실을 '건물 이름 + 호실'**(예: `행복빌라 2동 101`)로 표시 — 건물이 하나면 지금처럼 `101`
- 사업장 안에서 건물 이름은 겹칠 수 없음 (호실 구분의 기준)
- 합계(홈 수입·미납·결산·세무 준비)는 사업장 전체 기준

## 브라우저 시험 (`e2e/`)

실제 PostgreSQL·API·화면을 띄워 브라우저(Playwright)로 핵심 흐름을 확인합니다. GitHub Actions 의 `e2e` 작업이 PR 마다 실행하고,
실패하면 스크린샷·trace 를 올립니다. 화면 오류(콘솔 오류)가 하나라도 나면 실패합니다.

- 가입 → 호실 등록 → 청구 → 은행 내역(재업로드 중복 없음) → 매칭 → 홈('미납 (확인 전)')·임대료 검토 대기
- 입금 알림 연결 주소 → 로그인 없이 보낸 알림 → 홈 '오늘 납부일' 입금 확인 (틀린 주소 404)
- 정기 점검 추가 → 했음 기록 → 다음 예정일 → 되돌리기 / 공실 → 모집 조건 → 광고 문구 / AI 비서 '연결 안 됨'
- 휴대폰 폭 390px 에서 주요 화면 10개 가로 넘침 없음
- 건물 두 동: 같은 통장 함께 쓰기, '건물 이름 + 호실' 표시, 같은 건물 이름 거절
- 월간 보고서: 장부 값 그대로 요약, 엑셀 내려받기, 오지 않은 달 거절, 인쇄 화면에서 메뉴 숨김
- 임차인 링크: 만들기 → 로그인 없는 휴대폰 화면('입금 확인 전', 이름 없음) → 수리 요청 → 홈·수리 목록 → 링크 끄기

로컬: `cd frontend && ROOMAX_API_ORIGIN=http://127.0.0.1:8000 npm run build`, `cd e2e && npm ci && npx playwright install chromium`,
`ROOMAX_DATABASE_URL=postgresql://…/roomax_e2e npx playwright test` (서버는 시험이 직접 띄움, 백엔드 파이썬은 `E2E_PYTHON` 으로 지정)

## 운영 배포 (`deploy/`)

서버 1대에 `docker compose up -d --build` — Caddy(HTTPS 자동 발급·갱신) · 화면 · API · PostgreSQL · 정기 백업.
절차와 확인 목록은 [deploy/README.md](./deploy/README.md).

- 화면과 API 를 **같은 도메인**에 (`/api/*` 만 API 로). 세션 쿠키는 `Secure` · `HttpOnly` · `SameSite=Lax`
- `ROOMAX_ENV=production` 이면 시작할 때 설정을 검사해 **위험하면 띄우지 않음**: 암호화 키 없음, 쿠키 Secure 꺼짐,
  메일 링크가 http, 메일이 file 모드(실제로 안 보냄), DB 개발용 비밀번호. 운영에서는 `/docs` 닫힘
- `GET /api/v1/health` 는 DB 까지 확인 (끊기면 503) — 컨테이너 상태 검사·외부 가동 감시에 사용
- 정기 백업 파일은 소유자만 읽기(600), 이름은 한국 시각. 해지된 사업장의 백업은 30일 뒤 자동 삭제

## Vercel + Supabase 로 돌릴 때 (`ROOMAX_SERVERLESS`·`VERCEL=1`)

- 파일(계약서 원본·정기 백업·복구 직전 안전 백업)은 **Supabase Storage 비공개 버킷**에 (`ROOMAX_STORAGE=supabase`, 서버 키는 API 에만).
  서버리스인데 `supabase` 가 아니면 시작하지 않음
- DB 는 Supabase **Transaction pooler(6543)** — 연결 풀 없이(NullPool) prepared statement 끔. 마이그레이션은 GitHub Actions
  (`.github/workflows/db-migrate.yml`, Session pooler 5432 를 시크릿으로)
- Vercel 요청 한도 4.5MB: 계약서 사진은 화면에서 줄여 올리고(`frontend/lib/image.ts`), **백업 파일은 브라우저 ↔ Storage 서명 URL 로
  직접** 주고받음 (API 를 거치지 않음). 다 쓴 임시 파일은 정기 작업이 하루 뒤 정리
- 정기 작업: Vercel Cron → `GET /api/v1/internal/cron/daily` (`Authorization: Bearer $CRON_SECRET`, 비밀값이 없으면 404) —
  DB 조회(일시정지 방지) + `ROOMAX_BACKUP_PASSPHRASE` 가 있으면 사업장별 암호화 백업. Hobby 는 정한 시각의 1시간 안에 실행
- 메일은 응답 전에 바로 보냄 (서버리스에서는 응답 뒤 작업이 끊길 수 있음)
